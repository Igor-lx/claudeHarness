# claudeHarness

Обвязка для работы с кодом: правила качества, устройство базы знаний, счётный
инструмент, скиллы и заготовки всех файлов, которые нужны новому проекту.

Это не библиотека и не код — это **рабочий порядок**, который ставят в проект до
первой строчки кода.

**Слова здесь значат строго одно.** Если непонятно или забылось —
[`.claude/rules/glossary.md`](./.claude/rules/glossary.md): первым разделом там
восемь слов, без которых не читается ничего. Открывать можно посреди работы.

**Файлы обвязки становятся файлами проекта.** Скопировав `.claude` к себе, вы
получаете не зеркало и не кэш, а обычные файлы своего репозитория: их правят у
себя, коммитят вместе со своим кодом и проверяют своим же прогоном. Этот
репозиторий — только точка раздачи.

## Как поставить

```
git clone https://github.com/Igor-lx/claudeHarness.git tmp
cp -r tmp/.claude <ваш проект>/
rm -rf tmp
```

Дальше сказать ассистенту: **посади обвязку**. Он работает по инструкции внутри —
`.claude/seat/seat.md`.

**Если в проекте уже есть `.claude`** — не затирать её целиком: файл
`settings.local.json` принадлежит вам и вашей машине. Посадка это учитывает и
существующие файлы не перезаписывает.

**На macOS и Linux папка с точкой скрыта.** Копировать командой либо включить
показ скрытых файлов.

## Что внутри `.claude`

| | |
| --- | --- |
| `rules/` | доктрина: порядок работы, планка качества, устройство базы, правила записи и среды |
| `tools/` | счётный инструмент базы знаний, его справочник и словарь области |
| `skills/` | скиллы: вход в задачу, прогон проб, сверка готовности, смысловой проход, сборка для передачи |
| `seat/` | посадка: инструкция, карта и семена всех проектных файлов |
| `state/` | состояние самой обвязки: открытые вопросы и отложенное |
| `settings.json` | разрешения среды: что выполняется без вопроса, что спрашивается, что запрещено |
| `README.md` | описание обвязки для человека: что меняется в работе |

## Откуда это берётся

Правки идут не здесь, а в проекте, где обвязку можно **прогнать**: правило,
написанное и не проверенное прогоном, ничем не отличается от правила, которое не
работает. Проверенное уезжает сюда одной папкой, командой `handoff`.

Поэтому здесь лежит только та часть, что копируют. Истории правок она не теряет —
каждая публикация приходит отдельным коммитом.
