# План доказательности: машинные ворота, машинный пол, независимое суждение

Временный файл. Удаляется последним шагом плана, когда все шаги отмечены
сделанными; незакрытое к тому моменту переезжает в `todo.md` или
`questions.md` рядом.

Написан `2026-10-04` по слову разработчика: «декомпозируй на атомарные задачи,
полностью и подробно запиши, запушь; дальше делай по предложенному порядку и
объёму, коммить и вычёркивай каждый шаг». Работа продолжается в другой сессии,
на другой машине и под другим аккаунтом, поэтому файл обязан читаться без
единой строки прежнего контекста.

---

## Как работать с этим файлом

1. Прочитать файл целиком, до первого действия. Затем — доктрину по
   `.claude/rules/entry.md`, как обычно.
2. Найти первый шаг с `[ ]` — это следующая работа. Шаги идут в порядке
   исполнения; перескакивать нельзя, кроме случая, когда шаг явно помечен
   «можно параллельно».
3. Один шаг — один коммит. Тот же коммит отмечает шаг в этом файле: `[ ]` →
   `[x]`, и в строке шага после слова «сделано:» — что получилось, числами
   замера. Номер шага пишется в тело сообщения коммита строкой
   «plan step <номер>»: по нему шаг находится в истории (`git log --grep`).
4. Перед коммитом — проверки из подзаголовка «Испытательная посадка» ниже.
   Коммит — только при коде `0` у каждой; вывод читается до коммита, а не
   склеивается с ним в одну команду (`safety.md`).
5. После коммита — пуш в рабочую ветку, которую назначила среда, и перемотка
   `main` тем же коммитом: `git push origin HEAD:main`. Так в этом репозитории
   принято разработчиком: `main` всегда совпадает с последним сделанным шагом.
6. Шаг оказался больше, чем описан, — делится на подшаги прямо здесь, тем же
   коммитом, что и первый подшаг. Нашлось, что шаг неверен или не нужен, — не
   молча: строка «отменён: причина» и вопрос разработчику в `questions.md`.
7. Отчёт разработчику после каждого пункта — по `close.md`.

Сообщения коммитов — английские, Conventional Commits (`feat(stop): …`).
Комментарии в коде инструмента — русские, как вокруг. Подпись коммитов —
по правилам той среды, где идёт работа.

## Испытательная посадка

В репозитории обвязки нет ни `package.json`, ни базы `.context`: инструмент и
тесты гоняются в проекте, куда обвязка посажена. Посадка заводится один раз на
сессию, вне репозитория, и обновляется копированием `.claude` после каждой
правки. Процедура проверена `2026-10-04` с нуля: сверка базы — код `0`, тесты
словаря зелёные.

Завести:

```bash
H="$(git rev-parse --show-toplevel)"     # корень репозитория обвязки
F="${TMPDIR:-/tmp}/harness-seat"         # посадка: любая папка вне репозитория
rm -rf "$F" && mkdir -p "$F"
node -e '
const fs=require("fs"),p=require("path");
const [shelf,box]=process.argv.slice(1);
const map=JSON.parse(fs.readFileSync(p.join(shelf,"seat/map.json"),"utf8"));
const own=new Set(map.projectOwnedInsideHarness??[]);
for (const d of map.dirs) fs.mkdirSync(p.join(box,d),{recursive:true});
fs.cpSync(shelf,p.join(box,".claude"),{recursive:true,
  filter:(s)=>p.dirname(s)!==shelf||!own.has(p.basename(s))});
for (const one of map.copy){ if(one.notAtSeating!==undefined) continue;
  const dst=p.join(box,one.to); fs.mkdirSync(p.dirname(dst),{recursive:true});
  fs.copyFileSync(p.join(shelf,one.from),dst); }' "$H/.claude" "$F"
cd "$F"
npx -y npm@11 install --no-audit --no-fund
git init -q && git add -A
git -c user.name=seat -c user.email=seat@local commit -qm seat
git config core.hooksPath .claude/hooks/git
B=$(git rev-list --max-parents=0 HEAD)
sed -i "s#^  barSince: null,#  barSince: \"$B\",#" .context/graph.config.mjs
git -c user.name=seat -c user.email=seat@local commit -qam "barSince"
node .claude/tools/graph.mjs verify; echo "verify: $?"
```

Обновить после правки в репозитории — копия `.claude` без файлов настроек
проекта, удалённое в репозитории удаляется и в посадке:

```bash
node -e '
const fs=require("fs"),p=require("path");
const [src,dst]=process.argv.slice(1);
const own=new Set(["settings.json","settings.local.json"]);
const walk=(d,base,out=[])=>{for(const e of fs.readdirSync(p.join(base,d),{withFileTypes:true})){
  const r=p.join(d,e.name); if(e.isDirectory()) walk(r,base,out); else out.push(r);} return out;};
const keep=(r)=>!(p.dirname(r)==="."&&own.has(r));
const want=new Set(walk(".",src).filter(keep));
for(const r of want){fs.mkdirSync(p.dirname(p.join(dst,r)),{recursive:true});
  fs.copyFileSync(p.join(src,r),p.join(dst,r));}
for(const r of walk(".",dst).filter(keep)) if(!want.has(r)) fs.rmSync(p.join(dst,r));
' "$H/.claude" "$F/.claude"
```

Ловушки, на которых уже спотыкались:

- `npm install` версии `10` падает на семени без lock-файла ошибкой `edgesOut`

  обратных кавычках, иначе краснеет «Числа в прозе базы». Путь в обратных
  кавычках обязан существовать — путь будущего файла пишется без кавычек.
  Ссылка на раздел ставится только на существующий заголовок.
- `graph.mjs` целиком не отформатирован prettier; новый код форматируется как
  вокруг — сверить кусок можно `npx prettier` из посадки.
- Новая сверка заводится в трёх местах (`base.md`): код (`CHECK_SECTIONS` и
  `checkHead`), строка в `.claude/tools/checks.md`, рецепт в
  `.claude/tools/falsify.json`.
- Экспортированная функция одного аргумента в `graph.predicates.mjs` обязана
  иметь случаи в `PREDICATE_CASES` с обеими сторонами: самопроверка идёт на
  каждом вызове инструмента. Вердикт-функция возвращает пустую строку на
  «чисто».
- Новый держатель или критерий требует решения в матрице `bar-hold`: формы,
  которых держатель не видит, либо закрытый набор с причиной.
- Вложенные сессии (`claude -p`) и агенты — только по слову разработчика:
  дорого.

- **Не добавляем новых критериев планки**: их `208`, а машина решает по `25`.

### Пункт 1. Ворота конца хода и страж обхода ворот

Зачем: цель «обойти нельзя по построению». Сейчас сессия, кончившаяся без
коммита, не проходит ворот ни разу, а коммит без ворот агент делает одним
флагом без вопроса.

- [ ] `1.1` — **Страж обхода ворот git.**
  - Предикат `gitHookBypass(command)` в `graph.predicates.mjs`: пустая строка
    либо причина. Разбор оболочки: кавычки одинарные и двойные, экранирование;
    деление на команды по `;`, `&&`, `||`, `|`, `&` и переводу строки; тело
    встроенного документа (`<<EOF`, `<<'EOF'`, `<<"EOF"`, `<<-EOF`) до строки
    с меткой не разбирается. Команда — та, чьё первое слово `git` после
    присваиваний вида `X=1`. Глобальные ключи git перед подкомандой: `-C <путь>`,
    `-c <ключ=значение>`, `--git-dir=…`, `--work-tree=…`.
  - Причины: `commit` с `--no-verify` либо с коротким `n` в связке ключей до
    первого ключа с аргументом (`-nm` — да, `-am` — нет, `-mn` — нет: после
    `m` идёт текст сообщения); `-c core.hooksPath=…` перед любой подкомандой;
    `config` с `core.hooksPath`, если это запись либо снятие, а не чтение
    (`--get`, `--get-all`, `--list`, `-l`, либо имя без значения — чтение).
  - Случаи с обеими сторонами: обычный коммит — пусто; флаг внутри текста
    сообщения в кавычках — пусто; `echo git commit --no-verify` — пусто;
    флаг в теле встроенного документа — пусто; `cd a && git commit -n -m x` —
    причина; `git -C d commit --no-verify` — причина.
  - Режим `guard --hook`: разбирается В САМОМ НАЧАЛЕ `graph.mjs`, до чтения
    настройки и обхода дерева — хук зовётся на каждый вызов Bash, а обход стоит
    `~0.2` с и растёт с проектом. Читает JSON события из stdin; при
    `tool_name` равном `Bash` берёт `tool_input.command`. Причина есть — текст
    в stderr (что запрещено, почему, что делать: коммит делает разработчик
    сам либо ворота проходят сводом) и код `2`; иначе код `0`. Неразборчивый
    вход — код `0`: он не команда git.
  - Тест режимов: событие с запрещённой командой — код `2` и текст; с
    обычной — код `0`; в папке без `.context` режим работает так же (значит,
    не зависит от обхода).
  - Документация: режим в `graph.md`; в `safety.md` — абзац о `--no-verify`:
    в сессии флаг останавливает страж, вне её ловит ревизия по истории.
  - Готово, когда: тесты обвязки зелёные, сверка базы `0`, самопроверка
    словаря чиста.
