# Обоснование к `entry.md`

Почему порядок входа в файле `.claude/rules/entry.md` устроен так: случаи и
отклонённые варианты. Норма — в самом файле правил; здесь её не повторяют.
Заголовки те же, что у разделов нормы.

## Вход: что читать, в каком порядке и в какой момент

**Почему вход отделён от правил проекта.** Пока этот порядок лежал внутри
`CLAUDE.md`, общее и проектное правились одной правкой: доктрина уезжала в
следующий проект вместе с путями и командами предыдущего, а проектное терялось
при обновлении доктрины.

## Первыми же действиями, до любых действий с кодом

**Почему список разделён по моментам.** Плоский список отменял бы правило ярусов
из `loop.md` — «ярус меняет объём правил, которые грузятся до области», — и
отменял бы его из другого файла и без указания на это. Два правила об одном
предмете с противоположными требованиями исполняются так: действует то, которое
прочитано последним. Найдено мысленным экспериментом «снести свод верхнего
уровня и посеять обвязку заново»: плоский список загонял в безусловный вход
планку и правила документации целиком, то есть большую часть доктрины, — при
вопросе «где лежит этот хук».

**Почему ярус держит среда.** Прежде здесь стояло «сами эти файлы не
загружаются автоматически — их открывают по этому списку», и это было неверно:
среда кладёт в контекст каждый файл `.claude/rules/` без шапки `paths:`. Ярусы
тогда не отсекали ничего — при вопросе «где лежит этот хук» в контексте лежал
весь свод, — а вход по списку открывал загруженное второй раз. Замер — ниже,
абзац «Как правила попадают в сессию».

**Почему `close.md` и `base-format.md` приходят по шапке.** Каждая сессия
несла их со старта, около `32 400` знаков, хотя нужны они в два момента:
закрытие работы и запись в базу. Шапка `paths:` кладёт их ровно тогда:
`close.md` — с протоколом свода, без которого работа с кодом не
закрывается, `base-format.md` — с файлами базы и протоколом. Карта и факты в
шапку не входят: их открывают на каждом входе, и шапка вернула бы файл в
стартовый контекст. Отклонено открывать их одними руками: момент держала бы
одна память, а шапка — среда. Отклонено и снимать со старта `writing.md`:
прозу пишут в любом файле, момент по пути не опознать, а машинной опоры у
его правил нет — они ослабли бы без признака. Решение разработчика
`2026-10-16`.

**Как правила попадают в сессию.** Раздел нормы `environment.md` с этим
именем снят решением Р9 плана обвязки `2026-10-20`: действие стоит пунктом 2
порядка входа, механизм — здесь.

**Механизм — текстом нормы до переноса `2026-10-20`.** Действие — пункт 2
порядка входа `entry.md`; здесь — как среда кладёт правила и почему.

Правила проекта — `CLAUDE.md` и файлы `.claude/rules/` — среда кладёт в
контекст сама, без чтения; каждый виден в контексте блоком со своим путём.
Когда это происходит, решают два признака: шапка файла и папка, где стартовала
сессия.

| Что | Сессия стартует в папке проекта | Сессия стартует выше проекта |
| --- | --- | --- |
| `CLAUDE.md` и правила без шапки `paths:` | при старте | при первом чтении любого файла внутри проекта |
| правило с шапкой `paths:` | когда сессия открывает (Read, Write, Edit) файл под шаблон шапки | так же |
| настройки проекта `.claude/settings.json`: разрешения, запреты, хуки | действуют со старта | **не действуют** |

Вторую раскладку дают рабочей областью: папка с несколькими проектами, сессия
стартует в ней, проект лежит уровнем ниже. Механизм описан документацией среды
и снят замером на Claude Code `2.1.288`. Порядок входа (`entry.md`) от него не
зависит: файл, текст которого в контексте есть, второй раз не открывают, а
которого нет — открывают руками.

**Настройки среда читает только из папки старта.** При старте выше проекта его
список разрешений не снимает вопросов, запреты и «спросить» не действуют, а
хуки проекта не запускаются. Сверки объявления хуков этого не видят: файл
настроек верен, его просто не читают. Видит след стража: первый коммит и
первая сверка базы из такой сессии останавливают работу словами «хуки проекта
не исполняются» (справочник, режим `gate`).

Чинит это человек: сменить папку сессии Claude не может. Способов два:

- стартовать сессию в папке проекта;
- стартовать выше и сразу выполнить `/cd <проект>`. Начиная с Claude Code
  `2.1.246` команда переносит сессию в папку проекта и применяет её настройки,
  хуки и скиллы.

**В облачной сессии `/cd` нет**: команда отвечает «Changing the directory
isn’t available for this session». Там проект заводят репозиторием сессии, и
она стартует в его папке.

Сессия, увидевшая старт выше проекта, говорит об этом человеку один раз, в
начале работы. Признаки: `git status` в папке старта отвечает
`not a git repository`, а блока `CLAUDE.md` проекта в контексте нет до первого
чтения файла внутри.

**`@`-импорт разворачивается вместе со своим файлом правил**, то есть при старте
выше проекта — не раньше первого чтения файла внутри него. Свод на импорты не
опирается: доктрина лежит в `.claude/rules/` и приходит сама.

**Проект называет человек** — «работаем в `<проект>`» и следом `/cd <проект>`:
без команды хуки проекта не исполняются. В рабочей области нет файла, который
сказал бы сессии, где проект, раньше, чем она прочтёт что-то внутри него.

**Соседние папки рабочей области к работе не относятся.** Текущий проект
называет человек; остальные папки не предлагаются и не перечисляются в вопросе
«над чем работаем».

**Файла правил в корне рабочей области быть не должно.** Он не уезжает ни с
полкой, ни с проектом, и всё, что в нём записано, расходится с копиями
обвязки, не давая признака.

**Что из этого следует для правил проекта:** им нельзя предполагать, что они уже
загружены, и нельзя открывать второй раз то, что загружено. Первый пункт их
списка «первыми же действиями» обязан быть исполним из состояния «не прочитано
ничего».

**Как это установлено.** Механизм описан документацией среды — её страницами о
памяти, настройках и разрешениях — и снят замером на Claude Code `2.1.288`:
проект в подпапке папки старта, а хук, срабатывающий на каждую загрузку правил,
записывал файл и причину. На старте не загрузилось ничего. Первое чтение файла
внутри проекта принесло `CLAUDE.md` и правило без шапки, чтение файла `.ts` —
правило с шапкой под такие файлы. Хук старта сессии из настроек проекта не
сработал.

**Страница чтения тоже будит шапку.** Замер `2026-10-13`, Claude Code `2.1.296`,
чистая папка проекта: только `.claude/rules/` и файл первой страницы
в папке страниц протокола, сессия без хуков. Вопрос до чтения —
лежит ли в контексте текст `quality.md` — ответ «нет». Первое чтение
страницы инструментом Read принесло `quality.md`, `quality-scoped.md` и
`code.md` отдельными блоками с путями. Те же правила без образца
`**/bar-pages/*.md` в шапках: после того же чтения текста политики в контексте
нет, и страница лишь ссылается на файл. Отсюда образец в шапках трёх правил и
страницы чтения файлами (`tools/graph.md`, режим `bar-read`).

**Из шапки `code.md` образец снят.** Разбор журнала пробы `2026-10-13`: с
первой страницей приходил `code.md` целиком, `72 000` знаков, и лежал в
каждом следующем обращении, а своду из него нужны два раздела, на которые
ссылаются тела `A16` и `H3`. Их печатает страница критерия; на правке кода
`code.md` всё равно приходит по шапке файлов кода.

**Прежняя редакция ошибалась.** Она утверждала обратное: загружается файл правил
папки старта и только он, а при старте выше проекта не загружается ничего и
после чтения его файлов. Ссылалась она на пробу, и для версии выше это неверно
в обе стороны. Чем объясняется та проба, не установлено: версия среды не
записана, как и то, каким инструментом читались файлы.

**Цена прежней ошибки.** Файлы `.claude/rules/` весили `711` КБ, среда клала в
контекст все, вход по списку открывал их второй раз, а ярус «по поводу» не
отсекал ничего. Отсюда устройство доктрины: файлы о коде несут шапку `paths:`,
таблица сверок лежит вне `.claude/rules/`.

**Почему `/cd` назван не везде.** Замер `2026-10-06`: облачная сессия, стенд
посадки выращен во временной папке сессии, сессия стартовала в репозитории
обвязки — то есть выше стенда. Разработчик набрал `/cd` в стенд и получил
«Changing the directory isn’t available for this session». Хуки стенда не
исполнялись, и коммит в стенде из сессии остановил страж словами «хуки
проекта не исполняются». Прогон проб на этом стенде сузили до точек, которым
код стенда не нужен.

**Почему «больше не спрашивай» ложится в корень рабочей области.** На Windows и
вне git-репозитория среда пишет нажатое в местный файл настроек той папки, где
стартовала сессия.

**Почему файла правил в корне рабочей области быть не должно.** На другой машине
его нет, и любое правило, оказавшееся там, становится редакцией, которой нет у
обвязки нигде больше.
