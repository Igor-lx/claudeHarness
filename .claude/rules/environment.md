# environment — чтобы задача не вставала на подтверждениях

Правила и инструменты переносятся копированием папки; **настройки среды — нет**:
в новом проекте отсутствуют список разрешений и сведения о том, какие команды
требуют подтверждения, и задача, оставленная без присмотра, останавливается на
первом же запросе подтверждения. Этот файл задаёт настройки, при которых такая
остановка не возникает.

Всё изложенное ниже — наблюдения, снятые на работающих сессиях. Там, где
механизм не установлен, это сказано прямо. Замеры, опровергнутые догадки и
отклонённые варианты к разделам этого файла —
[`../rationale/environment.md`](../rationale/environment.md), под теми же
заголовками.

## Хуки обвязки

Тот же файл несёт хуки среды. Каждый зовёт режим инструмента:

| Событие | Режим | Что делает |
| --- | --- | --- |
| начало сессии | `transition`, `stop --session` | печатает переход и его долг; незаконченную работу и ход, кончённый без свода |
| правка файла | `transition --hook` | напоминает о переходе строкой в контекст |
| вызов Bash и Read | `guard --hook` | останавливает коммит мимо ворот: `--no-verify`, подмену `core.hooksPath`; чтение страницы свода оболочкой — страницы открывают Read; чтение протокола свода целиком или вне модели предмета — модель читает Read по окну из вывода `bar` |
| конец хода | `stop --hook` | не даёт кончить ход, пока правка кода не накрыта запечатанным сводом |
| сжатие контекста | `bar-read --stale` | гасит слова страниц в незапечатанных протоколах свода: прочитанное до сжатия в контексте не уцелеет |

**Хук зовёт обёртку без оболочки и от каталога проекта:** `"command":
"node"`, а путь `${CLAUDE_PROJECT_DIR}/.claude/tools/hook.mjs` и режим — в
`args`. Хук идёт в текущей папке сессии, и путь от неё из подпапки инструмента
не находит; подстановку среда делает до запуска, в любой системе одинаково.
Обёртка держит ход и коммит и тогда, когда инструмент не отработал
(справочник, режим `stop`). Пропуск хука, вызов мимо обёртки, путь от текущей
папки и поле `disableAllHooks` называет сверка
«Ворота конца хода и страж обхода включены».

Конец хода наступает и посреди работы — вопросом разработчику на развилке.
Тогда работа не закончена, и ход кончают паузой с причиной:
`stop --pause <причина>`. Пауза годна, пока правка не меняется, а причину
печатает начало следующей сессии.

## Что списком не снимается

Записи сверяются по началу команды. Склейка через `&&` разрешения **не
наследует**: разрешённой обязана быть каждая часть, поэтому `cd` в списке стоит
отдельно — без него любая команда вида `cd проект && npm test` будет спрашивать.

**Признак, по которому запрашивается подтверждение, не установлен.** Без
подтверждения проходили конвейеры, редиректы и склейки из многих частей, а
спрашивали и обход дерева каталогов, и `grep` по одному названному файлу.
Записывать догадку о механизме как факт нельзя.

**Обход есть, и он не требует знания механизма: поиск идёт инструментом
Grep — всегда**, включая поиск по одному конкретному файлу. Этот инструмент не
спрашивает никогда. За Bash остаётся то, где он незаменим: запуск команд и
фильтрация **их вывода** трубой.

**Инструментов Grep и Glob в среде нет — запасной путь один:** `grep` и `find`
оболочкой, одной командой, без трубы и без склейки; обе стоят в списке
разрешений семени. Выведено: в сессии `claude -p` Claude Code `2.1.304` обоих
инструментов не было, и вызовы отказаны «No such tool available».

**Отсюда белый список запуска вместо списка запретов.** Через оболочку идёт
только то, что показало себя устойчиво разрешённым: проверки проекта (`npm …`),
инструмент базы (`node .claude/tools/graph.mjs …`), форматирование и мутации
(`npx …`), разовый скрипт (`node <файл.mjs>`), копирование при синхронизации
полки (`cp`) и чтение состояния репозитория для отчёта (`git status`,
`git log`, `git diff`).

**Какие скрипты манифеста сессия не запускает — признак закрытый.** Сверка
«Скрипты манифеста описаны» требует, чтобы скрипт был назван либо таблицей
команд, либо списком исключённых. Признак для второго списка один, из двух
частей:

- **не отдаёт управление** — поднимает сервер, следит за файлами, не
  завершается сам. Сессия на таком вызове встанет и не вернётся;
- **меняет файлы** — исправляет форматирование или правила на месте. Правка,
  сделанная не по задаче, попадает в тот же коммит и читается как её часть.

Оба запускает разработчик у себя. Сверка проверяет **наличие решения**, а не его
правильность; без этого признака каждый заход решал бы заново.

**Всё остальное — инструментами.** В «остальное» попадают и команды,
которые в списке разрешений **стоят** и всё равно однажды спросили: `grep`,
`head`, `diff`, `find`, `sed`, `mv`, `printf`. Нужно сравнить два файла —
читать оба или писать разовый скрипт, а не звать `diff`.

## Отсюда раздел труда, а не отказ от Bash

| Задача | Чем |
| --- | --- |
| Запуск: `npm run check`, сборка, `graph.mjs`, `git status/log/diff` | Bash |
| Чтение любого файла | **только Read** |
| Поиск по репозиторию и по одному файлу | **инструмент Grep** — подтверждений не требует в принципе; нет его — `grep` одной командой |
| Перечисление файлов по маске | **инструмент Glob**; нет его — `find` одной командой |
| Правка и создание файлов | **Edit / Write** |

`Edit` отказывает в правке файла, не прочитанного **инструментом** `Read` в
этом же диалоге: файл, прочитанный через `cat`, потребует ещё одного вызова
`Read` перед правкой.

## Инструменты среды, которые правила обязаны назвать

Инструмент, не названный в правилах, не существует для того, кто их читает. Три
вещи называют поимённо и **в том разделе, где они применяются**, а не общим
списком:

- **команда ревью правки** — на узел, до коммита. Прогон с кодом ноль говорит
  «не сломано», а не «сделано хорошо»: он не видит ни лишней работы, ни
  разъехавшегося слоя, ни решения, принятого дважды;
- **команда запуска приложения** — когда правка видна на экране. Ни база, ни
  тесты, ни смоук не отвечают на вопрос «как это выглядит и ощущается»;
- **агент широкого поиска** — на сметания вида «найди все места, где…», чтобы
  выдача не оседала в основном контексте. Запускается по решению разработчика,
  но **предлагается тем, кто видит форму задачи**. Форма опознаётся по трём
  условиям сразу: десятки файлов; на выходе нужен список или вывод, а не текст
  для рассуждения; где смотреть, заранее неизвестно. Не выполнено одно — обычный
  поиск дешевле. Агент читает выдержками, поэтому область он **очерчивает**, а
  не заменяет, и его вывод подтверждается чтением названных им строк.

Названия у команд свои в каждом окружении; правило здесь про **место**:
инструмент вписывают в тот раздел, где он и нужен.

## Мелочи среды, ошибки в которых не дают признака

- **Рабочая папка Bash сбрасывается между вызовами.** Писать абсолютные пути
  либо `cd <проект> && …`, а не полагаться на то, что предыдущий `cd` ещё
  действует. Для git — `git -C <папка> …`: склейку `cd` с командой git Claude
  Code `2.1.304` спрашивает отдельной проверкой.
- **Труба уничтожает код возврата** — `safety.md`, раздел «Коммиты: атомарно
  по смыслу, а на риске — дробнее».
- **`tail` срезает начало отчёта.** У инструментов, печатающих несколько
  секций, первая — самая важная (покрытие карты). Смотреть `head`, а не только
  `tail`, иначе легко объявить проверку отсутствующей.
- **Пустой ответ поисковика — ещё не отсутствие файлов.** Прежде чем делать
  вывод «этого нет», перепроверить другим способом.

## Концы строк — политика репозитория, а не настройка машины

На машине с `core.autocrlf=true` рабочее дерево окажется в CRLF, и любая замена
многострочного фрагмента, ищущая по одному лишь `\n`, не найдёт ничего — без
признака и без ошибки. Устраняется одним файлом в корне — `.gitattributes`. Он
**приезжает семенем** и кладётся **до первого коммита**: заведённый позже, он
не перепишет уже лежащие файлы сам, их придётся переиндексировать.

## Как посадить в новый проект

Посадка — своя инструкция со своими фазами, картой семян и формой отчёта:
[`seat/seat.md`](../seat/seat.md). Экран `/permissions` показывает, какое
правило разрешений сработало; из сессии он не виден, поэтому смотреть его —
работа человека, а не агента.
