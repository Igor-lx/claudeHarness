## Как здесь работают

Порядок работы, планка качества, правила базы и среды — в `.claude/rules/`.
**Первым делом читается `.claude/rules/entry.md` целиком**: там состав
доктрины, момент чтения каждого её файла и то, какие из них среда кладёт в
контекст сама. Если его текст уже в контексте, второй раз его не открывают.

Ничего из доктрины в этом файле не повторяется. Файл правил проекта содержит
**только проектное** — то, чего нет и не может быть на полке: чем является этот
репозиторий, как он устроен, что отдаёт наружу, какими командами проверяется.
Повторённое расходится: пока общее и проектное правились одной правкой, доктрина
уезжала в следующий проект вместе с путями предыдущего.

## Устройство проекта

Раскладка умолчания обвязки, три слоя. Проект, разложенный иначе, переписывает
эту таблицу под себя и объявляет отступление решением.

| Слой | Что там | Единица переноса |
| --- | --- | --- |
| `src/app/` | корень композиции: точка входа, корневой компонент, их тесты | файл |
| `src/components/`, папка на компонент | он сам, его лист, тип карты классов, `tests/`, `docs/` | **папка** |
| `src/shared/`, папка на область | общее для всех компонентов | папка |

Направление одно: слой приложения знает про компоненты, компоненты знают про
общее, обратно — никто. Единица переноса компонента — его папка целиком, и
отсюда следует, что всё его содержимое лежит внутри неё, а не рядом.

Куда кладут новый узел: в слой по предмету узла — таблица выше и есть ответ.
Почему раскладка именно такая — `.claude/rules/code.md`, раздел «Раскладка
проекта». Держит это сверка «Новый узел лежит по раскладке».

**Проект со своей раскладкой переписывает таблицу под себя целиком**, вместе
с этим абзацем и абзацем про направление зависимостей: отвечать «куда кладут
новый узел» обязан он сам, своими папками, а не отсылкой к доктрине — там
описана другая раскладка. Требует этого сверка «Правила проекта не спорят с
реестром решений»: каждая своя папка верхнего уровня названа здесь путём.

<Что ещё специфично для этого проекта: слои сверх умолчания, их назначение и
направление зависимостей. Выводится из кода и заполняется по фактам с диска.>

**Законное, хотя со стороны читается нарушением:** <четвёртый слот ответа: что здесь законно, хотя со стороны читается
нарушением — намеренное дублирование, широкая поверхность, копия ради
изоляции. «Таких нет» — полноценный ответ, и его надо написать, а не
промолчать.

Слот отдельный потому, что это единственное в разделе, что из кода не
выводится: у нового проекта кода ещё нет, а правило нужно с первой строки.
Пока он стоял внутри общей скобки, ответ на остальное скобку закрывал, и
пропуск было нечем поймать. Названное здесь заводит запись в реестре решений:
законное, читающееся нарушением, обязано быть решением — иначе следующая
сессия примет его за недосмотр и «починит».>

## Как проверяется сделанное

Полный набор проверок проекта:

| Проверка | Команда |
| --- | --- |
| Сервер разработки | `npm run dev` |
| Сборка | `npm run build` |
| Посмотреть собранное | `npm run preview` |
| Типы | `npm run typecheck` |
| Тесты | `npm test` |
| Линт | `npm run lint` |
| Формат | `npm run format:check` |
| Покрытие (по требованию) | `npm run test:coverage` |
| Мутационный прогон по новым и изменённым файлам, после `--` ключ `--mutate` и файлы | `npm run mutate` |
| Всё разом | `npm run check` |
| Правка против её тестов, базы и доков | `node .claude/tools/graph.mjs tested` |
| Долг мутационного прогона по правке | `node .claude/tools/graph.mjs mutated` |
| База знаний | `node .claude/tools/graph.mjs verify` |

**Команды даны для `npm` — это объявленное умолчание.** Менеджер другой —
правятся эти строки, и только они: по всему своду `npm` больше не упоминается
как переменная. Строка, чьего предмета в проекте ещё нет, **убирается**, а не
оставляется пустой, и возвращается вместе с предметом.

Команды `tested` и `mutated` — часть **каждого** отчёта о правке кода, а не
«по требованию»: первая спрашивает про тесты, записи базы и документацию
тронутых файлов, вторая — про долг мутационного прогона. Проект без
мутационного прогона убирает вторую вместе с её строкой.

**Для каких правок прогон проверок не нужен вовсе:** <Если таких нет —
«таких нет, нужен всегда».>

## Эталонные узлы

<Заполняется, когда в проекте появятся свои файлы, на которые можно
показать пальцем. Критерии отбора — в quality.md, раздел «Эталонный узел».>

Схема стилизации при этом действует с первого дня и эталона не требует: она
описана словами в `code.md`, раздел «Как компонент разговаривает со своими
стилями». Файлов-примеров обвязка с собой не везёт — они были бы заготовкой
проекта, о котором ещё ничего не известно. Первый написанный по схеме
компонент и станет её эталоном.
