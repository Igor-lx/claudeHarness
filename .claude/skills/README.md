# Скиллы — памятка

> **Кладётся как `README.md` в папку скиллов проекта.** Побайтовой пары у неё
> нет и быть не может: состав скиллов у проекта свой — `purpose` заводят не на
> посадке, а когда своду будет что выводить. Строку скилла, который не заведён,
> из таблицы удаляют. Что состав строк совпадает с папками скиллов, сверяет
> `verify`.
>
> **Этот файл написан для человека.** Из общего стиля свода он выпадает
> намеренно: короткие фразы, никаких ссылок на разделы, никаких оговорок о
> границах.

Скилл — записанная инструкция, которая загружается **по вызову**, а не лежит в
памяти постоянно. Часть скиллов ассистент зовёт сам по ходу работы, часть —
только вы.

Две особенности, на которых спотыкаются:

- **список появляется не сразу после запуска сессии**, а по ходу работы с
  файлами проекта;
- **«в подсказке по `/` его нет» не значит «не установлен»**: вызов по имени
  срабатывает и тогда, когда в подсказке скилл ещё не показан.

## Что есть

| Скилл | Зачем | Кто зовёт и когда |
| --- | --- | --- |
| `task` | начать задачу с правильного яруса входа: определить класс задачи, прочитать ровно нужное, собрать «что придётся тронуть» одним вызовом инструмента | **ассистент сам**, в начале любой работы с кодом |
| `probe` | проверить обвязку выдуманными, но реалистичными задачами: ловят ли правила, база и инструмент правдоподобно-неверное действие | **вы**, когда надо убедиться, что обвязка правда работает, а не выглядит рабочей |
| `handoff` | собрать обвязку для передачи: папку `.claude`, готовую к копированию в чужой проект, плюс памятку получателю. Проверяет снимок посадкой в пустую папку | **вы**, когда отдаёте обвязку другому разработчику или переносите на другую машину |
| `audit` | оценить готовность обвязки: замеры, сплошное чтение на связность, оценка по разделам с весами, план улучшений с ценой | **вы**, периодически и перед крупной работой над обвязкой |
| `purpose` | проверить, достаточен ли набор инструкций для цели, ради которой он написан; находит классы дыр, под которые признака ещё нет | **вы**, редко: повод — событие, а не календарь. Свод существенно вырос или цель сместилась |

Заканчиваются отчётом и ждут решения **`audit` и `purpose`** — правок они не
делают. **`probe`** чинит найденное сразу, по общим правилам.

## Как позвать: `probe`

По умолчанию — **один прогон по горячему контуру**: то, что проверяется между правкой и коммитом
и что проверяется обычной петлёй «правка → проверки → коммит».

| Сказать | Что будет |
| --- | --- |
| «прогон проб», «прогон 7×7» | один прогон по горячему контуру, отчёт, остановка |
| «два прогона», «ещё раз» | названное число прогонов подряд, каждый новыми пробами |
| «повторяй до чистого» | повторять, пока прогон не даст ноль находок |
| «пройди по такой-то области» | тот же прогон, но пробы сужены до названной области |
| «проба по холодному контуру» | **вторая ось**: то, чего ежедневная петля не касается вовсе — заготовки для другого проекта, публикация, первый запуск в чистом клоне, вторые копии, проза без машинной проверки. Сама собой в обычный прогон не подмешивается |

## Как позвать: `audit`

| Сказать | Что будет |
| --- | --- |
| «сверь готовность», «аудит обвязки» | **полный ход**: замеры, оба сплошных чтения, оценка по разделам, план улучшений |
| «только правила», «пройди по своду» | **короткий ход по своду**: только связность правил и скиллов, без замеров и баллов |
| «пройди по докам», «аудит документации» | **короткий ход по документации**: только связность документов о продукте |

Короткие ходы есть потому, что связность портится чаще, чем меняются числа, а
замеры и оценка стоят дорого.

## Как позвать: `purpose`

Говорится «смысловой проход». Отличие от `audit`: тот спрашивает «правильно ли
мы всё измеряем», этот — «то ли мы измеряем и всё ли, что нужно».

## Если заводится новый скилл

Строка в этой памятке — часть той же правки, что и сам скилл. Расхождение
обнаруживает сверка базы: скилл без строки и строка без скилла одинаково
завершают прогон ненулевым кодом.
